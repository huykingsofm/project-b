# R6. Every pattern has at least one exemplar

For every pattern the design relies on (the plan index, the publish of state, the scheduler, a `table.Table` with a column, a standing action, a gate, dispatch by kind, bounce), build at least one working exemplar with its tests and a benchmark, even if no feature uses it yet. The exemplar shows later what the pattern looks like and what using it requires, so that design and code are settled before the first real use and not at the moment it is needed. An exemplar comes with a short note: what a user of the pattern must write, and what it costs. This is not premature optimization: the pattern is part of the design ([R5](r05-essentials-built-now.md)), and only an opt-in speedup waits. Exemplars today: `ZoneLayerCharacterShieldGrantAction` (a standing action that finds other actions in the plan), `ZoneLayerCharacterMoveAction` (an action that sets itself again, through a cooldown, and can be cancelled), `ZoneLayerCharacterRegenAction` (a cron), and `ZoneLayerCharacterExitToAction` (an optimistic action that reads what other scopes published and puts a character back when a message cannot be delivered).
