# Ways of working

- **Ask until it is clear before starting.** Ask until every point is clear; state the impact on later features before any work. When asking the owner to decide, also state the cases that one option handles and the others cannot, with the risk and the impact.
- **Run `make ci` before every reply, commit and push.** `make ci` runs the format check, `go fix`, `go vet`, the line length (`lll`), `go test -race` and every check added to it later (a new check is a new target in the `Makefile`). It is run, and passes, before every reply to the owner that reports work, and before every commit or push; never `--no-verify`. The pre-commit hook in `.githooks/` runs it on every commit (`make hooks` installs it, once for each clone). The result reported is the result of that run.
- **Commits.** Every commit has a subject and a clear body, wrapped at 72 columns. No `Co-Authored-By` line and no "Generated with ..." line of Claude. No "part X" in a commit message or in a PR title or body; splitting into parts is local planning.
- **Delete merged branches**, local and remote, once it is verified safe.
- **The plan is the source of work.** Read the plan fully at the start of every session and let it drive the work; whatever is decided and not yet done is recorded in the plan at its place. A refactor has no progress row of its own; only new rules and new pending work reach the plan.
- **Language.** Replies and the plan documents are written in Vietnamese, with technical terms kept in English (goroutine, channel, engine, zone, zonelayer, snapshot, tick, registry, adapter, interface, ...). Code, comments, commits, PRs and this rules file are written in English.
- **Benchmarks.** After any change that could affect performance or behavior, run the tests, the linter and the relevant benchmarks, compare with the previous numbers, and replace the numbers in `docs/benchmark/` in place, a file for each group of benchmarks. The file always shows the latest run, and its history is in git. Benchmarks are mandatory. Optional optimization features are deferred ([R4](r04-essentials-built-now.md)); a measured cost that is not a design problem is recorded for the profiling step and left alone.
- **Go 1.27.** The project uses Go 1.27 (`go.mod` says `go 1.27`): use generics fully (type parameters, constraints such as `comparable` or `cmp.Ordered`, generic types with methods) and the newer features of the language and the standard library when they make the code clearer: `range` over functions (`iter.Seq`, `iter.Seq2`), `min`, `max`, `clear`, the `slices` and `maps` packages, `math/rand/v2`. A change of Go version, up or down, is the owner's decision and is recorded here in the same change.
- **Rules.** Before a rule is written, the existing ones are read: a new convention goes into the rule it belongs to, a rule that it contradicts is changed, and rules that say alike are merged. A new numbered rule is written only when none fits, and the owner agrees.
