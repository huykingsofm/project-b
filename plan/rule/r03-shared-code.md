# R3. Where shared code lives (hard)

- **Use an external library when one exists.** Before writing a generic container or mechanism, look for a maintained external library that does the job and use it. Only when none exists is it implemented in `shared`.
- `shared` (at the root of the repository) holds what no external library provides, and is treated as a set of external libraries that we happen to write ourselves. Each one is **its own package**, has its own tests, and **imports nothing of the project** except other packages of `shared`. They carry no business of the game: no word and no concept of the game. A package of `shared` must read like a library that could move to a repository of its own without a change.
- **The plan and the scheduler are not shared code.** The plan (the actions of a tick sorted by priority, with a cursor and indexes by kind, target and engine) and the scheduler (actions that run at a tick; what repeats is an action that sets itself again) are how a game that runs in ticks runs its actions, so they live in the platform (`platform/sim`: `plan.go` and `scheduler.go`), generic over the type of state, never in `shared`.
- `platform` holds what any game that runs in ticks is made of, and knows nothing of this game: `platform/sim` (the interfaces `State`, `Action[S]`, `Command[S]`, `Message`; the plan, the scheduler, the registry an action is given, the codecs), `platform/runtime` (`engine`: the engine `Engine[S]` that runs any state; `router`: the router of the messages and the router of the directives; `stable`: the store of the published states and the board of acks; `cluster`: the cluster and its orchestrator), `platform/journal` (`eventlog`: the event log; `checkpoint`: the checkpoint files; `replay`: playing a cluster again from them) and `platform/config`. It never imports `server`.
- `server/game` holds this game: the states and the entities in them (`server/game/sim/state`), the actions, the commands, the tile map, the builder of the cluster. It imports `platform` and `shared`, and `server/cmd` wires them. A state, an action or a command that exists only for this game is here and never in `platform`.
- When in doubt whether something belongs to the platform or to the game, ask: does it mention or assume anything of this game (a world, a zone, a character, an item, a map)? If it does, it belongs in `server/game`. When in doubt whether something is "shared", ask: does it mention or assume anything of a game at all (an action, a tick, an entity, a priority)? If it does, it belongs in the platform or the game.
- **Common is not shared.** `shared` never takes a package because it is "common to the engines", and a package of `shared` never imports `platform`, `server` or anything else of the project. Being common to several engines does not mean having no business.
